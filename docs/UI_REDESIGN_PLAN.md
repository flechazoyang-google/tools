# Toolbox 工具内页布局与 UI 重设计方案 v2.0

> 状态：待确认 · 确认后按「先建组件库 → 逐组迁移 → 编译验证」实施  
> 范围：23 个工具内页 + 共享组件库升级

---

## 一、现状诊断（跨页面共性问题）

| # | 问题          | 典型表现                                                             |
| - | ----------- | ---------------------------------------------------------------- |
| 1 | **信息层级扁平**  | 输入、参数、结果、按钮全部平铺在一个 Column，无分组，视觉"一坨"（BMI、时间戳、Base64 尤其明显）        |
| 2 | **结果呈现不统一** | 有的裸 Text（时间戳）、有的 primary 色大字（单位换算旧版）、有的卡片；数值字体无 tabular 等宽，跳动时错位 |
| 3 | **反馈样式零散**  | 错误提示有的红字内嵌、有的 SnackBar；加载无指示；空状态缺失或只有一行小字                        |
| 4 | **主操作不突出**  | 按钮散落在内容流中间（二维码的"生成"在输入框下面），无"主操作=底部大按钮"的约定                       |
| 5 | **顶栏能力不足**  | 只有标题+返回，无副标题说明、无右侧动作位（保存/分享/清空类操作没地方放）                           |
| 6 | **滚动行为不一致** | 有的页面可滚有的不可滚；小屏溢出风险不统一                                            |

---

## 二、统一设计系统（新增 8 个共享组件）

一次开发、全站复用，这是本次重设计的核心收益点。

### 1. `ToolTopBar` 升级

```
[←]     标题（titleMedium·居中偏左）      [动作图标×0~2]
```

- 高度 56dp；返回键 44dp 圆形涟漪热区（保留现状）
- 新增 `actions: @Composable RowScope.() -> Unit` 右侧动作位
- 新增可选 `subtitle: String`（工具用途一句话，labelSmall·onSurfaceVariant），让用户进页即知工具用法
- **理由**：顶栏是全站唯一的"常量"，升级一次全部页面受益；副标题消除"进来不知道怎么用"的问题

### 2. `ToolScaffold` 页面骨架

```kotlin
ToolScaffold(title, subtitle, onBack, actions) { /* 分区块序列 */ }
```

- 统一：TopBar + 内容区（水平 16dp、分区间距 12dp、底部 16dp + navigationBars inset）
- 内容超过一屏自动可滚（verticalScroll 内建），小屏不溢出
- **理由**：解决滚动行为不一致；把"padding(16.dp) 写不写、写在哪"这个历史脏活一次性收敛

### 3. `ToolSectionCard` 分组卡片 ⭐核心

```
┌──────────────────────────┐
│ (可选小图标) 组标题        │  labelMedium
│  …组内控件…              │
└──────────────────────────┘
```

- `surfaceContainerLow` 底、18dp 圆角、16dp 内边距、可选标题行
- **理由**：这是治"信息层级扁平"的关键。把每页内容按语义切成 2~4 组（输入组 / 结果组 / 参数组），扫描效率立刻提升；卡片底色比 surface 高半档，分组边界可见但不吵

### 4. `ResultCard` 结果强调卡

```
┌──────────────────────────┐
│ 标签（labelSmall）         │
│ 128.50 美元               │  displaySmall·tabular
│ 辅助说明（可选）            │
└──────────────────────────┘
```

- `primaryContainer` 底、`onPrimaryContainer` 字、数值用 `fontFeatureSettings="tnum"` 等宽数字
- **理由**：用户进工具页第一眼看的就是结果。统一"结果=主色容器+最大字号"，所有计算类工具的结果位置和样式形成肌肉记忆；等宽数字防止实时刷新时宽度抖动

### 5. `KeyValueRow` 键值行

```
标签 ······················ 值
```

- 左 label（onSurfaceVariant）右 value（onSurface·tabular·右对齐），可选行尾图标
- **理由**：单位换算"全部单位列表"、拼豆"耗材统计"、汇率"货币对列表"都在手写这种行，统一后代码和视觉双收

### 6. `SegmentedTabs` 分段切换

- M3 `SegmentedButton` 单选组，用于**互斥分类**（单位换算的长度/重量、BMI 的公制/英制）
- **理由**：FilterChip 行滚动会暗示"可多选/还有更多"，分段控件表达"就是这几类里选一个"，语义更准；且宽度自适应，小屏自动折行

### 7. `LabeledDropdown` 标签下拉

- labelSmall 标题 + M3 OutlinedDropdown，用于**大量选项**（单位换算 40+ 单位、汇率货币）
- **理由**：沿用上次修复方向，再统一标签样式与高度（56dp），与 OutlinedTextField 对齐形成节奏

### 8. `FeedbackBlock` 四态反馈

```
Loading:  圆形进度 + "正在获取汇率…" + 可选重试
Error:    ⚠ 图标 + 错误文案 + [重试] 按钮
Empty:    ◻ 图标 + 引导文案（可含 [去添加] 按钮）
Success:  ✓ + 短暂提示（2s 自动消失，或常驻状态条）
```

- 统一图标尺寸、文案层级（titleSmall + bodySmall）、居中布局
- **理由**：汇率加载、密码箱空列表、扫码失败……每个页面现在各写各的。统一后用户对"出错了→看文案→点重试"形成一致预期

### 9. 按钮层级约定

- **主操作**：`Button`（filled），fillMaxWidth × 52dp，固定在内容流**末尾**或底部；一页只有一个红/主色实心按钮
- **次操作**：`OutlinedButton` 高 44dp，与主操作间距 8dp
- **行内轻操作**：`TextButton`（复制/清空/切换）
- **理由**：一屏一个主按钮是移动端最强可用性约定；现在二维码"生成"混在表单里、压缩"保存"和"重新选择"平级，都会改

## 三、逐工具布局方案

按交互形态分 6 组，同组共享同一布局骨架，实现"风格统一"。

### A 组：即时计算型（输入 → 实时结果）

**布局骨架：`[输入组卡片] → [结果卡] → [参考列表卡片]`**

#### A1. 单位换算

- 现状：分类 LazyRow + 两个下拉 + 裸大字结果 + 全单位列表，整体无分组
- 调整：
  1. 分类 FilterChip 行 → **SegmentedTabs**（8 类分两行自动折行或横向滑动）
  2. 输入框 + 从/到下拉 + 交换按钮 → 收进**一个 ToolSectionCard**，交换按钮移到两个下拉中间垂直居中（现状已接近，统一间距与高度）
  3. 结果 → **ResultCard**（数值+单位名分开：数值 displaySmall，单位 titleSmall 灰字）
  4. "换算到全部单位"列表 → ToolSectionCard 内 **KeyValueRow**，当前目标单位行加 primary 色加粗
- 理由：该页信息三段式（选类→输入→看结果→查参考）天然对应三个分组卡片；目标行高亮让"点列表切换单位"这个隐藏交互变得可见

#### A2. 汇率换算

- 现状：金额输入+两个"点击切换"FilterChip 平铺，"点击切换"是反直觉交互；空态只有一行小字
- 调整：
  1. 金额 + 从/到货币 → **LabeledDropdown**（货币码+中文名，如 "USD 美元"），交换按钮居中
  2. 汇率结果 → **ResultCard**，附"1 USD = 7.24 CNY"辅助行
  3. 更新时间 + 刷新 → 收进**状态条**（ResultCard 底部 labelSmall + 右侧刷新图标按钮）
  4. 无数据 → **FeedbackBlock(Error)** 带重试按钮（连"暂无汇率数据，请检查网络"的文案一起换成可操作反馈）
  5. 货币对列表 → KeyValueRow 组
- 理由：货币有 20+ 种，点击轮换FilterChip要点十几次才能换到想要的货币，下拉是正确形态；错误态给"重试"按钮比让用户退出去再进来友好得多

#### A3. BMI 计算器

- 现状：性别选择 + 身高体重滑杆/输入 + 结果全平铺，滑杆与数值的联动弱
- 调整：
  1. 顶栏 subtitle："根据身高体重评估健康状态（中国标准）"
  2. **基本组卡**：性别 SegmentedTabs（男/女）+ 公制/英制切换
  3. **测量组卡**：身高、体重各一行 = 左数值输入（右对齐大字）+ 右滑杆（weight 联动），单位 label 跟随
  4. **ResultCard**：BMI 数值 + 分类标签（偏瘦/正常/超重/肥胖，色带指示：正常绿、偏瘦黄、超重橙、肥胖红）+ 健康体重范围辅助行
  5. 底部参考卡：分类标准 KeyValueRow 列表（<18.5 偏瘦…）
- 理由：滑杆+数值双向联动是这类工具的最佳输入形态（单手可调、即时反馈）；结果卡里放"分类+色带"比裸数字信息密度更高，用户真正关心的是分类而不是 23.7 这个数

#### A4. 时间戳转换

- 现状：输入 + 互转结果平铺
- 调整：
  1. **模式 SegmentedTabs**：时间→戳 / 戳→时间（替代现在隐式的自动判断）
  2. 输入卡：值输入 + "现在"快捷按钮（一键填当前时间/当前秒级/毫级三个 chip）
  3. **结果卡**：同时给出本地时间 / UTC / 相对（x 天前）三种 KeyValueRow，点击行复制
  4. 单位切换（秒/毫秒）移到输入卡内
- 理由：时间戳工具用户最常做的事就是"现在是多少"；三种结果并排展示省去切换；点行复制比专门放复制按钮省空间

#### A5. Base64 编解码

- 现状：模式切换 + 输入框 + 输出框上下排
- 调整：
  1. **模式 SegmentedTabs**：编码 / 解码 / URL 安全变体（三个选项）
  2. 输入卡：多行输入 + 字符计数 + 清空 TextButton
  3. **结果卡**：输出文本（可选择复制）+ 主操作"复制结果"按钮 + 字节数辅助信息
  4. 输入即转换（去掉了独立的"转换"按钮）
- 理由：Base64 是纯函数无耗时，即时转换 + 一键复制是最短路径；字符计数对处理边界（padding、中文 UTF-8 字节数）有实际帮助

#### A6. 亲戚称呼计算器

- 现状：链条选择按钮 + 结果
- 调整：
  1. **链条编辑卡**：已选关系以"面包屑"呈现（我 → 父 → 兄 → 子），每段可点删除；下方候选词按词性分区（长辈/同辈/晚辈三行 FlowRow）
  2. **ResultCard**：称呼大字 + 对方怎么叫我（双向结果，现状只显示单向）
  3. 顶部"重置"移到顶栏 actions（清除图标）
- 理由：面包屑让当前链条一眼可读、可回退（现在选错了只能整体重来）；双向称呼是最常见疑问（"我该叫他啥/他该叫我啥"）

### B 组：生成型（输入 → 产物预览）

**布局骨架：`[参数卡] → [预览区] → [底部主操作条]`**

#### B1. 二维码

- 现状：输入框 + "生成"按钮混在表单里 + 图片 + 扫码识别两个功能平铺
- 调整：
  1. 顶栏 actions 放"扫一扫"（相册识码入口收进顶栏，页面只保留生成主线）
  2. **内容卡**：文本输入（多行）+ 快捷类型 chips（文本/网址，网址自动加 https 前缀）
  3. **预览区**：居中卡片（白底内衬 24dp，二维码 240dp），长按/点击出"保存到相册"底部条
  4. 输入即生成（去 debounce 300ms）；扫码结果用 FeedbackBlock + 复制按钮
- 理由：生成是零成本操作，"点生成"是多余步骤；白底内衬保证深色主题下二维码可扫（黑码白底是扫码器的事实标准）；识码入口放顶栏后页面职责单一

#### B2. 密码生成器

- 现状：长度滑杆 + 字符集勾选 + 结果文本 + 重新生成按钮
- 调整：
  1. **ResultCard 置顶**：生成的密码等宽大字 + 强度指示条（四段色条：弱/中/强/极强）+ 复制主按钮
  2. **参数卡**：长度滑杆（带刻度 6-32）+ 四个字符集 Switch 行（大写/小写/数字/符号，行尾显示示例字符）
  3. "重新生成"= 参数卡右上刷新图标；改参数即时重新生成
- 理由：结果置顶符合"我最关心密码本身，参数偶尔调"的使用频率；强度条给了普通用户最需要的判断依据（这是同类产品的标配）

#### B3. 文本差异对比

- 现状：两个输入框 + 对比按钮 + 结果
- 调整：
  1. **左右双栏卡**：原文/修改文两个等高多行输入（小屏上下堆叠，`BoxWithConstraints` 断点 480dp），各带字数与清空
  2. 对比即时触发（输入停止 500ms）
  3. **结果卡**：diff 行渲染（删除行 errorContainer 底红字、新增行 primaryContainer 底，行号对齐等宽字体），顶部统计条 "+3 −1"
- 理由：双栏并排是 diff 的心智模型（GitHub/Beyond Compare 都这样）；统计条让"改了多少"无需细读

### C 组：传感器沉浸型（全屏即工具）

**布局骨架：`顶栏(半透明) + 全屏取景 + 底部数据条`**

#### C1. 尺子 / C2. 水平仪 / C3. 指南针（同骨架）

- 现状：各自为政的布局，水平仪和指南针数据读数位置不统一
- 调整：
  1. 顶栏保留但内容区全屏铺开（去掉边距，尺子刻度顶到屏幕边缘才是"真尺子"）
  2. **底部数据条**：半透明 surfaceContainer 高 64dp，水平仪=双角度数值、指南针=方位+度数、尺子=cm/inch 切换 SegmentedTabs；数值统一 titleLarge·tabular
  3. 指南针罗盘居中放大（min(宽,高)×0.7），方位文字随盘旋转
  4. 无传感器 → FeedbackBlock(Empty)
- 理由：沉浸型工具的"工具本体"应该占满屏，数据读数固定底部形成稳定锚点；三个页面共享骨架后学习成本趋近于零

### D 组：沉浸操作型（单焦点大界面）

#### D1. 计算器

- 现状：上表达式预览 + 下键盘，等号键已修过；历史无
- 调整：
  1. **显示区**（占屏高约 30%）：当前输入 titleLarge 右对齐 + 上一步结果 bodyMedium 灰字（"= 128"）
  2. 键盘区固定 5×4 网格，键高 = 剩余高度/4（自适应大屏），数字 surfaceContainerHigh、运算符 secondaryContainer、等号 primary、AC/DEL errorContainer 字色——**四档键色**建立功能分区的视觉语法
  3. 长按 DEL = 清空；横屏（宽>480dp）改 6 列加历史侧栏
- 理由：等号 primary 实心 + 右下角是计算器 app 的宇宙级惯例（iOS/小米/华为计算器全如此）；四档键色让用户余光定位按键

#### D2. 番茄钟

- 现状：进度环 + 数字 + 按钮平铺
- 调整：
  1. **中央焦点**：进度环（直径 min(w,h)×0.55）包时间 displayLarge·tabular；环颜色按阶段换（专注=primary、短休=tertiary、长休=secondary）
  2. **阶段指示**：环下方三个小圆点表示今日完成轮数，当前阶段用 SegmentedTabs 可切换（不可用阶段置灰）
  3. **底部主操作条**：开始/暂停主按钮（fillMaxWidth 圆角 28dp）+ 重置 TextButton
  4. 环绕动画：阶段切换时环做 scale 弹性过渡
- 理由：番茄钟使用场景是"放在桌上瞟一眼"，displayLarge 数字+大进度环保证 1 米外可读；阶段色区分让瞟一眼就知道现在是专注还是休息

### E 组：列表管理型

**布局骨架：`顶栏(含主操作) + 摘要条 + LazyColumn 列表`**

#### E1. 倒数日

- 现状：列表 + FAB 添加
- 调整：
  1. **置顶卡片**：最近的一个事件（大号剩余天数 displayMedium + 名称 + 进度条）——倒数日的灵魂是"最关心的那个日子"
  2. 列表项：左侧色条(4dp·事件色) + 名称 + 日期小字 + 右侧剩余天数（正数灰字/负数"已过 x 天" primary 色），卡片化
  3. 空态 → FeedbackBlock(Empty) 带"添加第一个纪念日"按钮
  4. FAB 保留（右下角，expanded 尺寸）
- 理由：置顶卡把高频信息从列表里提出来，打开即见；色条+天数右对齐让列表可快速扫描

#### E2. 密码箱

- 现状：SETUP/LOCKED/UNLOCKED 三态布局已成型，细节不统一
- 调整：
  1. **锁定/设置页**：居中锁定图标（48dp 圆形容器）+ 标题 + 说明 + 密码框 + 主按钮；错误提示统一为输入框下方 error 色小字+震动反馈
  2. **列表页**：搜索框（名称/账号过滤）+ LazyColumn；条目卡 = 图标(首字母圆形) + 名称 + 账号小字，点开展开显示密码/备注/操作（复制/编辑/删除收进展开区，不再四个按钮平铺）
  3. 锁定按钮移到顶栏 actions（锁图标）
- 理由：条目默认收起密码是安全惯例；展开式交互把"查看密码→复制"变成自然的两步；搜索是密码多了之后的刚需

#### E3. 经期记录

- 现状：记录列表 + 预测信息
- 调整：
  1. **本月日历卡**：月视图网格（经期满 primary 圆点、预测日 outline 圆圈、今天描边），点击日期记录/取消——比纯列表直观一个量级
  2. **预测卡**：下次经期/排卵日/易孕期三行 KeyValueRow + 距今天数
  3. 历史列表收进第三组卡（可折叠）
- 理由：日历是经期类产品的唯一正确形态（对照美柚/Flo）；三行预测是用户记录的根本目的，必须一屏可见

### F 组：图片处理型

**布局骨架：`[源图区(占位/预览)] → [参数卡] → [结果统计条] → [底部主操作]`**

#### F1. 九宫格切图 / F2. 图片拼接 / F3. 图片压缩 / F4. 加水印 / F5. 取色器 / F6. 拼豆图纸（同骨架分述）

- 共性调整：
  1. **未选图状态**：全宽虚线边框选图卡（相机图标 + "点击选择图片" + 支持格式说明），替代现在的裸按钮
  2. **已选图**：预览区固定最大高度 40% 屏高居中，右上角"更换"图标
  3. **参数卡**：每个工具的可调项收进同一卡片（见下）
  4. **底部主操作条**：主按钮(生成/保存) + 结果统计（如"2.1MB → 640KB · 压缩 70%"）固定底部不随内容滚动
- 分工具参数卡：
  - 九宫格：3×3/2×2/4×4 SegmentedTabs + 导出边距开关
  - 拼接：方向 SegmentedTabs(横/竖) + 已选图片横向缩略图条(可拖动排序×可删除) + 间距滑杆
  - 压缩：格式 SegmentedTabs(JPEG/WebP/PNG) + 质量滑杆(带预估体积) + 目标宽高开关
  - 水印：文本输入 + 位置九宫格选择器(3×3 小格子点选) + 字号/透明度滑杆 + 平铺开关
  - 取色器：大图取色模式 + 放大镜跟随 + 已取颜色色板条(最近 8 个)
  - 拼豆：板型 SegmentedTabs(29/52/58) + 调色板选择下拉 + 网格预览(可捏合缩放) + 耗材统计 KeyValueRow 收进可折叠卡
- 理由：六个图片工具共享"选图→调参→出图"三步心智，骨架统一后用户学会一个就会全部；固定底部操作条保证生成/保存按钮永远可点（现在要滚到底）；压缩的体积对比数字放按钮上方，是用户决定"保存还是再调"的直接依据

## 四、响应式与可达性约定

| 场景             | 策略                                          |
| -------------- | ------------------------------------------- |
| 小屏 (<360dp)    | SegmentTabs 折两行；文本差异上下堆叠；计算器键盘保持 4 列（键高自适应） |
| 大屏/平板 (≥600dp) | 内容区 max-width 600dp 居中；文本差异左右双栏；计算器右侧出历史栏   |
| 横屏             | 图片工具预览区左、参数右双栏                              |
| 深色主题           | 全部用主题 token，二维码/拼豆预览强制白底内衬                  |
| 数字跳动           | 所有动态数值 `tnum` 等宽                            |
| 触达             | 主按钮高 52dp；列表项高 ≥64dp；点击热区 ≥44dp             |
