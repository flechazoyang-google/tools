# 待办台账 · 写作契约

> 本目录（`backlog/`）集中存放各工具的未完成项台账。**台账内容本身不入库**（见根目录
> `.gitignore`：`backlog/*` 除本 README 外全部忽略），公开的只有这份契约与管家脚本
> `scripts/backlog.mjs`。原因：仓库是公开的，"我们知道但没修的缺陷"不该对所有人可见，
> 而方法值得复用。换机器时台账需自行同步。

## 一、命名

一个工具一个文件，文件名用 `ToolCatalog.kt` 里的 **tool id**：

```
backlog/countdown.md      # 倒数日
backlog/period.md         # 经期记录
backlog/calculator.md     # 计算器
```

管家靠这个文件名 + front matter 的 `tool:` 与 `core/registry/ToolCatalog.kt` 对齐，
所以文件名和 `tool:` 必须一致且真实存在（对不上就是 error）。

## 二、文件结构

```markdown
---
tool: countdown                    # 必填，ToolCatalog 里的 id
plan: docs/COUNTDOWN_REDESIGN_PLAN.md   # 选填，关联方案文档（路径需存在）
baseline: v1.1.3 → v1.2.0          # 选填，本轮改造的基线
released: v1.2.0                   # 选填，已随哪些版本发布（逗号分隔多个）
updated: 2026-09-10                # 必填，台账自身最后修订日期
---

# 倒数日 · 未完成项台账

（背景、版本占位说明等散文，随便写）

## 二、总览

| 编号 | 类型 | 标题 | 重要程度 | 计划版本 | 状态 | 登记时间 |
| --- | --- | --- | --- | --- | --- | --- |
| COUNTDOWN-P1-01 | 🛠 | 一句话标题 | **P1** | v1.2.x 补测 | ⬜ | 2026-09-10 |

## 三、明细

### COUNTDOWN-P1-01 · 🛠 完整标题

| 项 | 内容 |
| --- | --- |
| **类型** | 工程 / 质量 |
| **重要程度** | **P1** |
| **计划版本** | v1.2.x 补测 |
| **现状** | …… |
| **要做什么** | …… |
| **验收** | …… |
```

### 总览表是唯一的机器可读入口

七列**列名与顺序都不能改**（管家按列名匹配，改了就解析不到 → error）。
一张台账只认一张这样的表，多余的同结构表会被忽略。

| 列 | 取值 | 约束 |
| --- | --- | --- |
| **编号** | `<工具前缀>-P<阶段>-<序号>`，如 `COUNTDOWN-P1-03` | 全仓唯一（跨台账也不能重）；明细小节的 `### 编号 ·` 必须在总览里存在 |
| **类型** | 🐞 缺陷 · ✨ 功能扩展 · 🎨 体验优化 · 🔒 合规/隐私 · 🛠 工程/质量 | 可组合（`🔒 + ✨`）；用别的符号只是丢失分类，不报错 |
| **标题** | 一句话 | 会进总览，别写成长句 |
| **重要程度** | `P1` / `P2` / `P3`（`**P1**` 加粗形式也认） | 非法值 → error |
| **计划版本** | `v1.3.0`（精确）· `v1.2.x`（区间）· `—` / `未排` | 命中**已发布**版本且状态仍 ⬜ → error（说明发版时没核销） |
| **状态** | ⬜ 未开始 · 🔄 进行中 · ✅ 已完成 | 非法值 → error |
| **登记时间** | `YYYY-MM-DD` | 用于算账龄（僵尸项提醒） |

明细表里若写了 `**计划版本**` / `**重要程度**`，必须与总览一致（不一致 → error，
这类分叉恰恰说明台账已经在骗人）。

## 三、管家

```
node scripts/backlog.mjs                    # 生成 backlog/OVERVIEW.md + 控制台摘要 + 体检
node scripts/backlog.mjs --check            # 只体检，有 error 退出码 1
node scripts/backlog.mjs --check --release v1.3.0   # 附带"本次要发的版本还有 P1 没做完"
node scripts/backlog.mjs --list P1          # 只看某个重要程度
```

体检分两档：

- **error（拦发版）** —— 台账不可信或承诺没兑现：列名/取值不合契约、编号重复、
  `tool:` 不存在、明细与总览分叉、已发布版本还挂着未核销的 P1、
  `--release` 指定的版本还有 P1 处于 ⬜。
- **warn（只提醒）** —— 不拦：哪些工具一条待办都没登记（覆盖缺口）、
  P2/P3 登记超过 180 天仍未开始（僵尸项）、P1 却"未排期"、`updated` 落后于最新登记。

`scripts/release.ps1` 已在改版本号之前接了一步 `--check --release v<版本>`，
只拦 error。确实要带着已知缺口发版时用 `-SkipBacklogCheck`（会打 warn，别养成习惯）。

## 四、发版后要做的两件事

1. 把该台账的 `released:` 补上刚发布的版本、`updated:` 改成当天。
2. 本次没做完的项**改成未来版本或 ✅**，别让它留在已发布版本号上 —— 否则下次发版会被
   "未核销"拦住（这是刻意的：让台账没法长期撒谎）。
